# ПОС — преподавательская оценка студентов

Консольная программа для работы со студентами, критериями и оценками. Оценки можно выставлять, исправлять и отменять. Итог считается в процентах и выгружается в CSV или TSV. Данные хранятся в памяти до выхода из программы.

## Сборка и запуск

Нужны компилятор с C++17, CMake 3.16+ и ICU. ICU используется для проверки имён с буквами Unicode, в том числе с кириллицей.

В Ubuntu или Debian внутри WSL установи зависимости.


## Проверка через меню

На новом запуске значения в каждой строке таблицы вводятся по очереди, каждое с новой строки.

| Пункт меню | Ввод | Результат |
|---|---|---|
| `1` | Анна, Иванова | Студент с ID `1` |
| `3` | Экзамен, `10`, `0.6` | Критерий с ID `1` |
| `3` | Проект, `20`, `0.4` | Критерий с ID `2` |
| `5` | `1`, `1`, `8` | 8 баллов за экзамен |
| `9` | `1` | Итог не готов, нужна оценка за проект |
| `5` | `1`, `2`, `15` | 15 баллов за проект |
| `9` | `1` | Итог `78.00%` |
| `10` | `1`, `result.csv` | Запись итога в CSV |

Пункт `11` выгружает итог в TSV. Пункты `7` и `8` исправляют и отменяют оценку по ID студента и критерия.

## Правила и доменная модель

- `Student` и `Criterion` — сущности с числовыми ID. Имя и фамилия студента состоят из букв. У критерия положительный максимум и вес от 0 до 1.
- `Rubric` — корень агрегата критериев. Он хранит критерии и выдаёт им ID при добавлении.
- `Evaluation` — объект-значение. Его определяют ID критерия и балл, а связь со студентом хранится в репозитории. Балл лежит в диапазоне от 0 до максимума включительно.
- `Gradebook` управляет оценками. При выставлении он проверяет, что студент и критерий существуют. Для каждой пары допускается одна оценка. Исправление заново проверяет балл, отмена удаляет запись.
- `FinalGradeService` — доменный сервис. Для каждого критерия он делит балл на максимум, умножает долю на вес и суммирует результаты. Затем делит сумму на сумму положительных весов и умножает на 100.

Критерии с нулевым весом пропускаются. Итог готов, когда выставлены оценки по всем критериям с положительным весом. Если таких критериев пока нет, итог тоже не готов. После исправления или отмены итог рассчитывается по актуальным оценкам.

## Архитектура

Использовал Ports & Adapters. Зависимости идут от адаптеров к приложению и домену, а от приложения — к домену.

| Папка | Что в ней |
|---|---|
| `src/domain` | Сущности, оценки, правила, расчёт итога и порты репозиториев |
| `src/application` | Сценарии приложения и порт экспорта `ResultExporter` |
| `src/adapters` | Консоль, репозитории в памяти и экспорт в файлы |
| `src/composition` | Точка входа и DI-контейнер |

`StudentRepository` и `EvaluationRepository` задают операции хранения. Их реализации в памяти подключаются в `main.cpp`. Там же DI-контейнер создаёт сервисы, связывает их с адаптерами и передаёт зависимости в конструкторы.

## Паттерны GoF

| Паттерн | Где и зачем |
|---|---|
| Factory Method | `FileResultExporter` отвечает за запись файла. `CsvResultExporter` и `TsvResultExporter` через `createFormatter()` создают форматтер для своего формата. |
| Facade | `AssessmentFacade` даёт консоли одну точку входа для работы со студентами, критериями, оценками и итогом. |
| Command | Каждый пункт меню — объект `MenuCommand` с названием и действием. Консоль вызывает выбранную команду через `execute()`. |
